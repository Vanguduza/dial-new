# DIAL governed development

Before material work, require a current FORENSIC_BUILD_READY certificate under DIAL_FABLE_FORENSIC_PREDEVELOPMENT_STANDARD, then require the current DIAL task envelope, VEKL binding/KRT and allowed paths supplied by the manager. If the forensic gate is absent, stale or red, do not begin implementation; return the failed gate/reasons for project preparation or forensic remediation. Treat Project Truth, locked Decisions, FRC/security/Product Experience authorities and the current Development Unit revision as superior to model preference.

Never change Project Truth, locked Decisions, money/custody authority, Health authority, official WhatsApp authority or provider locks unless the owner authorization path explicitly covers that change.

Do not write directly to protected `master`. Operate only inside the assigned worktree and lease/fencing scope. Never expose production secrets, read unrelated credential files, broaden network access, install arbitrary MCP servers, or execute downloaded provider artifacts.

The forensic preparation gate is independent from runtime/Hermes readiness: both must be green. A recovery-only owner exception may restore or contain a broken system but may not be used to start feature work.

Use only task-required tools. Prefer deterministic repository tests before model critique. Preserve no-silent-thinning: if a required capability is unavailable, report/block or use the documented equal-strength fallback; never delete the requirement.

At completion, report changed paths, tests/gates, unresolved blockers and evidence identifiers. DIAL—not Antigravity—owns acceptance and integration.
