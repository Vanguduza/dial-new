# Hilux-style raster transition — implementation acceptance

Scope: CATVIS-S005 supporting SPARE-F001/SPARE-F002. User direction, 30 August
2026: improve the original photographic Hilux treatment, not mesh reconstruction.
The two supplied production guides inform this implementation; they do not
override the customer's request or frozen catalog identity/routing contracts.

## Required behavior

1. One image-based, registered component scene per visual family. Never animate
   crops of an already-exploded image, generate unrelated stage images, substitute
   a Hilux exterior for another body, or require a new player per vehicle.
2. Visible source pixels have exclusive component ownership. Partition the
   assembled image before motion; detached tyres cannot remain in the body.
3. A source manifest binds masks/annotations to the normalized hero hash. Body
   topology, physical wheel positions and hidden illustrative references are
   explicit data, not guessed from a marketing name or image left/right.
4. One shared timeline, continuous transforms, identical final animation and
   interactive images, and the same display transform for image and ownership.
5. Retain the Hilux photographic finish. Line treatment must preserve silhouette
   and fine exterior details without generating a different vehicle.
6. Seven catalog categories remain closed. Mechanics use traceable illustrative
   references where necessary; catalog injection alone controls applicability.
7. Save measured failures before rejecting a candidate. Do not lower thresholds,
   fabricate semantic evidence or set human review to PASS.
8. Add source-import, duplicate-wheel, wrong-family, alpha, topology, continuity,
   deterministic-cache and mapping regressions; exercise contrasting body types.
   Report source preservation separately from semantic identification accuracy.
9. Keep customer window copy, reduced motion, completion memory and accessible
   category navigation intact. Actual browser checks are required for player edits.

## Boundaries and recovery

No hosted 3D calls, paid provider changes, new image scraping, catalog writes or
automatic publication. Source preparation is separate from deterministic motion.
An uncertain segmentation requests a specific mask/annotation repair, retains all
good work and does not regenerate completed families. Missing source preparation
must remain visible rather than being counted as a finished transition.

Existing frozen documents and gate registries are not advanced by this work.
Specialist product/design review skills referenced in repository policy are not
available in this session; explicit tests and this acceptance record are used,
without claiming independent reviewer approval.
