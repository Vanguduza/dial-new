# Full Platform Functional Completeness Gates

A top-level Feature ID is not implementation-complete by itself.

## Gate FR-0 — Realization mapped
- parent feature exists;
- all 9 mandatory facets exist, including Security/Privacy;
- donor strategy explicit;
- app/operator surfaces explicit;
- relevant supporting capabilities linked.

## Gate FR-1 — Workflow complete
- state/commands/queries/events;
- valid actions;
- eventualities/recovery;
- degraded paths.

## Gate FR-2 — Experience complete
- every customer/operator state has a usable surface;
- customer issue/support paths;
- human escalation;
- mobile/web/WhatsApp parity according to channel capability;
- accessibility/data saver.

## Gate FR-3 — Donor assimilation complete
- revision/source paths;
- provenance/licence;
- preserve/replace/add;
- parity tests;
- DIAL divergence tests.

## Gate FR-4 — Cross-domain complete
- Ledger/Delivery/RCE/Customer360/Vehicle/etc integrations tested;
- no duplicate SoR;
- Command Centre projection/controls.

## Gate FR-5 — Security profile green

- SECURITY_PRIVACY facet implemented;
- Feature Security Profile resolved;
- applicable security controls tested/evidenced;
- no blocking security finding.

## Gate FR-6 — Evidence green
- tests;
- security;
- visual where relevant;
- resilience;
- migration revalidation;
- evidence indexed.
