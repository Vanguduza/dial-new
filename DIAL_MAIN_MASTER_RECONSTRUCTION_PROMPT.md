## PORT-WHOLESALE exception

The general goal of architecture/business-rule independence does **not** mean rewriting founder-designated wholesale application donors from scratch.

For `PORT-WHOLESALE` donors such as **FixItNow → Dial a Tech**:

- pin donor revision and licence/provenance;
- copy the applicable donor repository/application wholesale into controlled import/quarantine;
- preserve mature application/UI structure where useful;
- remove automatic upstream production dependency;
- replace donor auth, database/business authority, payments, jobs and other SoRs with DIAL contracts;
- add all missing DIAL functionality;
- test behavior/UX/security/performance independently.

Do not cheap-recreate FixItNow merely to claim independent source expression.

## Performance/accessibility

Minimum targets:
- LCP ≤ 2.5 s
- INP ≤ 200 ms
- CLS ≤ 0.1

Use progressive enhancement: semantic content → CSS → light motion → cinematic sequences → WebGL.

Design mobile separately; do not simply shrink desktop cinema. For reduced motion provide equivalent static/simple experiences. Meaning must never exist only in animation. Canvas/WebGL is not the semantic content layer.

## Security/failure/performance

For strategic modules/donors explicitly cover threat boundaries/authn/authz/tenancy/secrets/uploads/audit, duplicates/reordering/stale/concurrent commands, DB/network/queue/process/config failures, retries/rollback/compensation/reconciliation/operator repair, and load/latency/query/cache/lock/queue/storage behavior.

Historical donor bugs and unusual tests are engineering knowledge. Convert them into DIAL invariants and regression tests.

## No upstream production dependency

Donors are research/import inputs. No automatic upstream Git pulls, donor webhooks, donor remote control plane, uncontrolled auto-updates, donor telemetry or runtime package resolution that gives upstream control over production.

## Definition of Ready

A strategic donor-derived capability is not ready until blueprint mapping, donor role, QDRS/QRP depth where applicable, UX target, state/data/authority, edges/failures, security, integrations, performance and acceptance tests are known, with no critical unresolved unknown.

## Definition of Done

A capability must pass applicable Blueprint parity, desired donor behavioral parity, desired UX parity, DIAL-specific enhancements, failure/concurrency, security, integration, performance, accessibility, independence/controlled-wholesale, observability/support/reconciliation and documentation/evidence.

Premium web also requires cinematic quality, mobile, reduced-motion, Core Web Vitals and visual QA gates.
